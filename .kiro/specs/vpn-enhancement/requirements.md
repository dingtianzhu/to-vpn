# VPN 增强优化需求文档

## 简介

本文档描述 ToVPN 项目的第二阶段优化需求，重点解决 SOCKS 模式系统级代理、流量/延迟数据真实性、服务器列表刷新机制等问题。

## 术语表

- **SOCKS 代理**: 应用级代理协议，端口 1080
- **HTTP 代理**: HTTP/HTTPS 代理协议，端口 1087
- **sing-box API**: sing-box 核心提供的本地 API 接口，用于获取流量统计和延迟数据
- **模拟数据**: 当 API 不可用时生成的随机假数据（需移除）

---

## 需求 1: SOCKS 模式系统级增强

**用户故事:** 作为用户，我希望 SOCKS 模式能代理更多应用，包括终端和不支持系统代理的应用。

### 验收标准

1. WHEN 用户启用 SOCKS 模式 THEN 系统 SHALL 同时启动 SOCKS (1080) 和 HTTP (1087) 代理端口
2. WHEN 系统代理设置 THEN 系统 SHALL 同时配置 SOCKS 和 HTTP 代理
3. WHEN 用户查看设置页面 THEN 系统 SHALL 显示代理配置说明（终端环境变量设置）
4. WHEN 用户断开 VPN THEN 系统 SHALL 同时清除 SOCKS 和 HTTP 代理设置

---

## 需求 2: 流量统计数据真实性

**用户故事:** 作为用户，我希望看到的流量统计是真实数据，而不是模拟的假数据。

### 验收标准

1. WHEN sing-box API 可用 THEN 系统 SHALL 从 API 获取真实流量数据
2. WHEN sing-box API 不可用 THEN 系统 SHALL 保持上次的流量值，速度显示为 0
3. WHEN sing-box API 不可用 THEN 系统 SHALL NOT 生成模拟的假流量数据
4. WHEN 流量数据无法获取 THEN 前端 SHALL 显示 "--" 或 "N/A"

---

## 需求 3: 延迟数据真实性

**用户故事:** 作为用户，我希望看到的延迟数据是真实测量值，而不是随机生成的假数据。

### 验收标准

1. WHEN VPN 已连接 THEN 系统 SHALL 通过代理测试真实延迟
2. WHEN 延迟测试失败 THEN 系统 SHALL 返回特殊值（-1 或 9999）表示无法测量
3. WHEN 延迟测试失败 THEN 系统 SHALL NOT 生成模拟的假延迟数据
4. WHEN 延迟无法测量 THEN 前端 SHALL 显示 "--" 或 "N/A"

---

## 需求 4: 服务器列表实时刷新

**用户故事:** 作为用户，我希望服务器列表能实时获取最新数据，延迟显示准确。

### 验收标准

1. WHEN 用户点击刷新按钮 THEN 系统 SHALL 清除缓存并从 API 获取最新服务器列表
2. WHEN 用户进入服务器列表页面 THEN 系统 SHALL 检查缓存是否过期（超过 1 分钟）
3. WHEN VPN 已连接 THEN 服务器延迟测试 SHALL 通过代理进行
4. WHEN VPN 未连接 THEN 服务器延迟测试 SHALL 使用直接 TCP 连接

---

## 需求 5: 带宽限制优化

**用户故事:** 作为用户，我希望 VPN 能充分利用我的网络带宽。

### 验收标准

1. WHEN 生成 Hysteria2 配置 THEN 系统 SHALL 使用优化的带宽限制（默认 500/1000 Mbps）
2. WHERE 用户自定义带宽 THEN 系统 SHALL 使用用户设置的值
3. WHEN 带宽设置过低 THEN 系统 SHALL 提示用户可能影响速度

---

## 实施优先级

1. **P0 - 立即修复:** 流量/延迟数据真实性（需求 2, 3）
2. **P1 - 短期优化:** 服务器列表刷新（需求 4）
3. **P2 - 中期改进:** SOCKS 系统级增强（需求 1）
4. **P3 - 长期优化:** 带宽限制优化（需求 5）
